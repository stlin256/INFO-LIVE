### [健忘的 CPU（M4 上的 Linux）](https://yuka.dev/blog-2026-10-02-linux-m4.html)
<div class="original-title-sub"><span class="orig-tag">原文</span> The forgetful CPU (Linux on M4)</div>

<div class="article-body" data-article-body="true"><p>这篇博文较为详细地介绍了我最初如何在 M4 Mac mini 上启动 Linux。我建议你自行查阅不熟悉的术语和概念，因为我无法在本文中解释所有背景知识；）</p>
<p>在继续之前，我首先要感谢整个 Asahi Linux 团队此前所做的所有工作，以及他们在这一过程中提供的帮助。如果你希望看到更多在 Apple Silicon 上推进主线 Linux 的工作，请考虑向 Asahi Open Collective 捐款！</p>
<p>2024 年 11 月，我买了一台 M4 Mac mini，赌的是它会与 M1 至 M3 Apple Silicon 设备相似，因此可以很快获得 Asahi Linux 的支持。在 M4 放在我桌上几个月的时间里，关于这款 SoC 的更多细节开始逐渐浮现。</p>
<p>事实证明，事情更加困难，因为 M4 设备是首代强制要求 SPTM（安全页表监控器，Secure Page Table Monitor）的 Apple Silicon。SPTM 可用于强化 macOS XNU 内核，抵御漏洞。在此前的几代产品中，Linux 的移植工作很大程度上依赖于使用 m1n1 虚拟机监控器捕获的 MMIO 跟踪信息，从而分析 macOS 原始驱动程序与硬件之间的交互。有了 SPTM 之后，必须对 m1n1 做出重大修改，才能让 macOS 在虚拟机监控器下运行；而对于这个领域的新手来说，这些修改显然超出了我的能力。不过，事情也并非毫无希望。在进行虚拟机监控器工作的同时，我开始首次尝试在 M4 上启动 Linux。这意味着要关闭严格的启动安全机制、通过 macOS 恢复环境将 m1n1 安装为自定义启动对象¹，并获取串行控制台²来检查日志。</p>
<p>既然我已经知道 Linux 代码确实在执行，我再次研究起此前为何尽管设置了 earlycon 启动参数，却仍然没有在串行控制台上看到任何 printk 输出。</p>
<p>当时，m1n1 没有启动次级 CPU 核心，因为缺少 smp_start_offset（这是 m1n1 中硬编码的一个偏移量；没有它就会跳过 smp_init）。我尝试使用基础版 M1 至 M3 所采用的偏移量，并成功启动了次级核心。再次尝试加载 Linux 后，我遇到了另一次神秘崩溃。</p>
<p>看来，这个“chicken bit”要么在 M4 上被锁定了，要么已经被移除，而其默认行为也不符合 ARM64 规范（具体来说：“如果系统配置为可以完成 WFI 指令，那么 WFI 指令就不得导致架构状态丢失。”⁵）。2026 年 4 月，我通过将内核中的所有 WFI 和 WFIT（带超时的中断等待，Wait For Interrupt with Timeout）指令替换为 NOP（空操作），成功在所有核心启用的情况下于 M4 上启动 Linux。</p>
<p>由此，一段寻求 WFI 问题上游解决方案的漫长旅程开始了。起初，我研究了通常如何处理勘误（芯片的异常行为）。Linux 中有一整套框架，允许系统在早期启动期间对内存中的自身代码进行修补。然而，这种方法被放弃了，因为很难准确检测哪些情况下应该将 WFI 替换为 NOP。具体而言，在 macOS 虚拟机监控器下运行的虚拟机也会触发勘误处理逻辑，但 WFI 会被 macOS 虚拟机监控器截获，并用于高效调度不同的客户机。检测虚拟化状态（尤其是在启用嵌套虚拟化时）同样很复杂，因此 Will Deacon 提出了另一种解决方案：内核应通过新增的启动参数⁶支持禁用 WFI 空闲机制；随后，m1n1 可以在已知 WFI 存在缺陷的裸机设备上启动时，有条件地加入相应的启动参数。之后，我们还会加入一种机制，使 Linux 能够让核心进入睡眠状态。目前可以使用下游的 cpuidle-apple 驱动实现这一点，不过 Sven 关于 PSCI EFI 通道的工作，为未来的上游解决方案带来了很大希望。</p>
<p>我很高兴地报告，防止 Linux 因 WFI 和 WFIT 指令而崩溃的机制已经合并进主线 Linux⁷ ⁸ 和 m1n1⁹，因此它们的最新版本现在可以在 M4 Mac 上原生启动，并启用次级核心！</p>
<p>截至目前，这项工作已经发现并解决了在 M4 及后续 Apple Silicon 芯片上运行 Linux 时的一个根本性问题，使 Linux 能够在所有核心均可使用的情况下启动至 shell（在 M4 Pro、M4 Max 和 M5 芯片上也发现同样的 WFI 变通方案有效！）。外设的逆向工程工作——这里不再详述——正在缓慢但稳步地推进。Sven 不知疲倦地致力于让 m1n1 虚拟机监控器能够在这些设备上启动并跟踪 macOS，这将对处理内置摄像头、显示控制器和 GPU 初始化等更复杂的组件非常有帮助。在大多数情况下，我会直接将自己的工作提交给相应的上游项目，让所有人都能从中受益。有时，如果一些获得大量资金支持的项目能更透明地说明它们如何从上游项目的进展中受益，那就更好了。</p>
<p>如果你想支持我在 M4 上开展 Linux 工作，可以通过 LiberaPay 或 GitHub Sponsors 捐款。也请考虑向 Asahi Open Collective 捐款，以支持更多在 Apple Silicon 上推进 Linux 主线化的工作。</p>
<p>一如既往，希望你能有所收获：）</p>

### [我们希望与英格兰居住在临时住所（包括住宿加早餐旅馆和酒店）中的无家可归者交谈](https://www.theguardian.com/society/2026/oct/02/homeless-people-england-temporary-accommodation-bbs-hotels)
<div class="original-title-sub"><span class="orig-tag">原文</span> We would like to speak to homeless people in England living in temporary accommodation including B&amp;Bs and hotels</div>

<div class="article-cover"><img src="https://i.guim.co.uk/img/media/aaea2cb25a38c6786981d10274c7a76d93faa84a/441_0_4325_3460/master/4325.jpg?width=140&amp;quality=85&amp;auto=format&amp;fit=max&amp;s=87f9a068764c434493af8a1991e4a08f" alt="我们希望与英格兰居住在临时住所（包括住宿加早餐旅馆和酒店）中的无家可归者交谈" loading="lazy" /></div>

<div class="article-body" data-article-body="true"><p>你在这处临时住所住了多久？居住条件怎么样？</p>
<p>政府近期公布的数据显示，2025年4月至2026年3月期间，英格兰各地议会为无家可归家庭提供临时住所支出了29.3亿英镑。</p>
<p>这笔金额包括住宿加早餐旅馆、酒店以及配备独立生活设施的住所。</p>
<p>据无家可归者慈善机构Shelter称，这相当于每天804万英镑，五年间增加了88%。</p>
<p>8月公布的数据显示，135,580个无家可归家庭目前居住在临时住所，其中包括177,530名儿童。</p>
<p>英格兰地方政府为无家可归者提供临时住所的成本预计将增加一倍以上，到2029—2030年度接近40亿英镑。英格兰地方政府协会（LGA）表示。</p>
<p>不过，英国政府已承诺在本届议会任期结束前停止使用住宿加早餐旅馆。</p>
<p>我们希望与被安置在住宿加早餐旅馆、酒店等临时住所中的人交谈。你在那里住了多久？居住条件怎么样？有人向你提供永久住房吗？</p>
