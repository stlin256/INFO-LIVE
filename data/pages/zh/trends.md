### [我已经被谷歌取消收录了](https://kennyqin.com/deindexed-by-google/)
<div class="original-title-sub"><span class="orig-tag">原文</span> I&#39;ve Been Deindexed by Google</div>

<div class="article-body" data-article-body="true"><p>我不记得具体是什么时候了，但在今年早些时候，我决定不再希望这个网站被搜索引擎收录。这在很大程度上与人工智能以及如今困扰互联网的无休止抓取有关。我知道，只要我的博客能被公共互联网访问，就没有什么真正的方法能阻止它，但至少有一部分规则会得到遵守。</p>
<p>我一开始是在 robots.txt 中设置了全局禁止访问（blanket disallow）。</p>
<p>在等待并检查了几周后，当我发现这并没有起任何作用时，我设置了 robots 元标签（meta tag）。</p>
<p>我以为这样就行了。但我当时没有意识到的是，讽刺的是，你实际上必须允许负责取消收录的爬虫访问你的网站，这样它才能看到那条告知它不再收录你页面的元标签。</p>
<p>我还对其他几款常见的爬虫进行了同样的操作，每当发现自己的网站已被取消收录时，就将它们从 robots.txt 中移除。</p>
<p>距离我为了让谷歌取消收录而做出最后一次更改已经过去了至少 3 个月，在今天检查之后，我很高兴地宣布，这个网站终于摆脱谷歌了！🥳</p></div>

### [一篇关于 API 的吐槽](https://dev.clintonblackburn.com/2026/10/08/a-rant-about-apis.html)
<div class="original-title-sub"><span class="orig-tag">原文</span> A rant about APIs</div>

<div class="article-body" data-article-body="true"><p>过去几周，我一直在努力实现 Vori 入驻流程的自动化，其间不得不与几个不同的 API 集成。这些 API 所对应的系统包括合同生成与电子签名收集、开票/计费系统、客户关系管理系统（CRM）、银行卡处理商和网关，以及刷卡终端供应商。</p>
<p>它们各自都有各种各样的问题。如果这些 API 面向的是新领域、承担的是新颖工作，那多少还可以接受；但这些解决方案都已经存在了十年甚至更久。更令人沮丧的是，开发者完全可以直接借鉴现有的、更优秀的 API 和实践，从而做得更好！</p>
<p>下面是一些我个人特别反感的问题。</p>
<p>如果我必须登录才能阅读你的 API 文档，那你已经搞砸了。你们居然真的写了文档，这一点值得肯定，但我为什么还要登录！？为了阅读文档，我不得不中断当前工作流，填写表单或给你们的支持团队发邮件，然后等待几个小时甚至几天！？</p>
<p>我曾向一个团队抱怨过这件事，他们也承认给文档设置访问门槛并不理想。不过，一位高管想要追踪潜在客户。搞什么！？我们已经是客户了。这个潜在客户已经赢单了。还有什么可追踪的！？</p>
<p>在代理式开发中，这个问题更加严重。我更愿意直接提供文档链接，让代理自行探索模式、构建客户端并完成集成。但设置访问门槛会打断这一流程。现在我不得不以某种方式下载文档——幸运的是，相关服务提供商提供 Markdown 格式——再把文档交给代理。每个端点都要这样处理！</p>
<p>直接取消文档的身份验证要求吧。你们这是在浪费自己的时间和资源，只为了让其他人也浪费他们的时间和资源。这是一个双输局面。</p>
<p>举手示意一下：有谁喜欢手写 API 客户端？如果你举手了，我不信。OpenAPI 规范已经存在 15 年了。到了现在，发布一个没有 OpenAPI 规范的 API，简直就是对人的不尊重。你为什么不喜欢我？我想给你钱的时候，你为什么要让我的日子更难过？帮帮我，也就是帮你自己。给我一份规范，这样我就能生成类型化客户端，把精力集中在自己的业务上。</p>
<p>哦，你说“这里有一份 Postman 集合”？我想，有总比没有好，但现在我还得想办法把它转换成 OpenAPI 规范。我们为什么要在一种低劣的格式上浪费时间？把好东西给我！</p>
<p>这和给文档设置访问门槛是类似的问题。API 需要凭证。废话，当然需要。让我自己生成和轮换凭证吧。为什么我得等上好几周，等 IT 团队生成凭证、切换某个开关，或者做类似的事情？事情总会发生。有时我们需要轮换凭证。不要让我为了一个潜在的安全事件提交支持工单！这意味着，周六出现的问题，很可能要等到周一中午有人看到工单后才能解决。</p>
<p>所以，你们创建了自助式凭证签发功能。很好。但等等！现在你又告诉我，这个凭证与创建它的人的身份绑定。也就是说……所有日志都归属于这个人，因此根本无法区分来自我们后端应用的 API 调用和这个人在你们 Web 应用中发起的调用？也就是说……只有这个人能够轮换凭证，而由于你们的应用要求单点登录（SSO），并且我们总得在账户共享这类糟糕做法上划条线，所以我们不能简单地共享凭证？也就是说……停用这个人的账户几乎肯定会导致一次事故？</p>
<p>我正在积极迁离一家采用这种做法的电子签名服务商，因为我是那个设置账户的人，而我目前正在休假；结果大家都无法查看合同——当然了，我当然希望所有发给杂货商的合同都关联到我的账户！我对供应商的疑问和筛选标准又增加了。</p>
<p>Webhook 非常适合构建近实时的工作流。我喜欢它们。但对于前面提到的那家电子签名服务商，我可是一点好感都没有：它要求在保存 Webhook 之前先验证端点。“你问什么叫验证？”很简单（也很愚蠢）：服务商向该端点发送一个负载，只有当端点返回成功响应时，服务商才会保存新的 Webhook 配置。</p>
<p>任何 Webhook 集成指南最前面的章节之一都会讲安全性。始终使用共享密钥验证负载，并在不进行处理的情况下拒绝无效负载。可是……没有共享密钥就很难完成验证，而服务商在端点被验证为可正常工作之前，又不会给我共享密钥。🙃</p>
<p>这就是为一个本不需要存在的问题设计出的荒谬变通方案：</p>
<p>我为此提交了一张支持工单，但回复我的人似乎不太明白这种工作流程为什么有问题。不过，他们确实明白我正在迁离他们的产品，于是突然想找我聊天，听取反馈。</p>
<p>值得一提的是，我甚至还没讨论 API 的模式和资源。大多数公司在 RESTful API 这方面做得都不错：用易于理解的名词和动词来定义业务概念与操作。尽管已经有超过 15 年的时间可以直接照搬 Stripe，老牌支付公司却出于某种令人费解的原因，仍然在这方面苦苦挣扎。真的，直接照搬 Stripe API 吧。我们花了大量时间和精力把它做出来。它很好用。拿去吧。</p>
<p>即使开发者体验糟糕透顶，我还是很高兴有人在构建 API。我们大体上在四周左右消除了一个包含 40 多个步骤的流程。当然，代理大约只用了 4 个小时就写完了代码，而这四周里的大部分时间都在等待凭证；但进步就是进步。</p>

### [要闻：……随后他们冲着纳维-斯托克斯方程（Navier–Stokes）来了，我什么也没说，因为我从未研究过纳维-斯托克](https://scottaaronson.blog/?p=10169)
<div class="original-title-sub"><span class="orig-tag">原文</span> The Mathocalypse</div>

<div class="article-body" data-article-body="true"><p>……随后他们冲着纳维-斯托克斯方程（Navier–Stokes）来了，我什么也没说，因为我从未研究过纳维-斯托克斯方程。但当他们冲着RL与L（RL vs. L）的问题来时，我意识到事情严重了。<br />——本博客的好友奥梅尔·莱因戈尔德（Omer Reingold，经授权分享）</p>
<p>昨晚，我9岁的儿子这样嘲弄我的妻子、复杂度理论学者达娜·莫什科维茨（Dana Moshkovitz）：“妈妈，听说你被干翻了！我听说有个机器人解开了你整个人生事业都在攻克的数学难题！噢天哪！”</p>
<p>虽然我儿子表现得像个顽童，但他说的倒也没错。无论你对此是感到兴奋、沮丧、愤怒，还是其他任何情绪，昨天无疑都是数学史上最重大的日子之一。是的，在OpenAI昨天公布的372项重大成果中（这是在其由蒂莫西·高尔斯、爱德华·威滕以及其他著名数学家组成的顾问小组建议下发布的），赫然包含了苏巴什·霍特（Subhash Khot）的“唯一定理猜想”（Unique Games Conjecture，简称UGC）的证明——这一命题从我认识我妻子以来，她就一直在全力以赴尝试证明它。（UGC意味着一大类优化问题确实是NP-难的，即使你只是想要一个稍微优于半正定规划松弛所能给出的近似解，而半正定规划正是我们的主要工具之一。）</p>
<p>或者至少可以说，我们相当确信这是一个证明！它附带了一个Lean证书，正如那372项突破性成果中的一部分所具备的一样（并非全部都有）。但目前似乎还没有任何人类能够理解这其中几乎任何一个证明；去理解它们的竞赛才刚刚开始。如果你想实地感受一下这场竞赛将是什么样子，以下是达娜昨晚给我发的一些短信：</p>
<p>“读起来感觉像是一个吃了迷幻药的人写出来的东西。太多的地方不清楚、讲不通。大量罗列以往成果的名字，却丝毫不讨论为何在存在‘不可能结果’（impossibility results）的情况下这些成果依然能被使用。”<br />“基本上，这篇论文写得太糟糕了，没有AI的帮助根本读不下去。”<br />“我向Astra询问噪声构件（noise gadget）合理的完备性与可靠性主张，它通过汇总论文各处的论述给出了答案。”<br />“他们还针对UGC的主要应用（最大割问题以及所有约束满足问题CSP），给出了绕过UGC的直接最优NP-难近似证明。”<br />“这一UGC证明发明了一种带噪声测试的、全新的诡异编码。这是一种疯狂的递归构造。”<br />“它既不是长码（long code），也不是短码（short code）——而是一种外星人式的疯狂构造。”<br />“我仍然认为，也许存在一个利用半空间编码（这是很自然的）的证明。”<br />“引文往往毫不相干且令人费解。”<br />“一种可能的未来是：如果你拥有远见/创造性想法，并能让AI协助核验与实现，那么这样的数学世界将是无比美妙的天堂。”<br />“当然，我们也有很多需要向这些外星人学习的地方。”</p>
<p>如果你好奇达娜此刻心情如何——嗯，可能五味杂陈，各种情绪都有吧！尽管一个核心的事业抱负败给了一个机器人，但对她而言至少有两个缓和因素。首先，她可以感到释怀和欣慰，因为UGC终究是被证明正确的，这是她从未怀疑过的，即使她的许多同行曾抱有疑虑！其次，我们所有从事数学、理论计算机科学和数学物理学的人，至少是那些关心解决定义明确的问题的人，现在都坐上了同一条船。</p>
<p>除了唯一定理猜想之外，以下是我在接下来的几周里可能会重点关注的、来自这个“阿拉丁神灯宝库”中的一小部分精选珍宝：</p>
<p>上述任何一项成果单独拿出来，都足以轻易当选某一领域的“年度最佳成果”（在某些情况下，例如唯一定理和L=BPL，甚至能问鼎整个计算机理论领域的年度成果）。而且我遗漏了许许多多的内容——欢迎大家在评论区尽情分享那些让你们目瞪口呆的内容！在数论、组合数学、代数几何、分析数学以及几乎所有其他数学领域，都有同样令人叹为观止的奇迹，其中大部分我永远都无法理解，不过我注意到其中包含了对黎曼猜想、霍奇猜想以及贝赫和斯维讷通-戴尔猜想（即剩余的千禧年难题的大多数）的部分进展。</p>
<p>我们可以从清单中缺少的内容中获得一丝慰藉。P≠NP不在其中，甚至连P=BPP或NEXP⊄P/poly也没有出现，而这绝对不是因为没有尝试过。显然，理论计算机科学最伟大的未解之谜确实相当棘手！</p>
<p>哦，免得我忘了：就在OpenAI发布成果的前一天，也就是周一晚上，弗吉尼亚·威廉姆斯（Virginia Williams）和乔希·阿尔曼（Josh Alman）在arXiv上发布了一篇预印本，以O(n1.9992)的时间复杂度解决了3SUM问题，并以O(n2.9995)的时间复杂度解决了全对最短路径问题，驳斥了半个世纪以来认为正确答案分别为n2-o(1)和n3-o(1)的猜想。在这个案例中，提供关键思路的并不是OpenAI的模型，而是Anthropic的模型！但随后Anthropic采取了与OpenAI截然不同的策略：他们没有将未经消化的解答直接抛给全世界，而是为弗吉尼亚和乔希提供了机会，让他们在获得报酬的前提下撰写并公布一个经过梳理消化的版本。</p>
<p>这已经演变成传播AI数学突破的两种主要模式，它们各有利弊。“OpenAI模式”引发了人类之间一场消化和解释杂乱AI证明的疯狂竞赛（这项工作很容易沦为费力不讨好、几乎得不到署名认可、充满竞争且毫无乐趣的事），而“Anthropic模式”则让一家私营公司处于挑选哪些人类数学家有资格充当AI使者的特权地位。我说不好，大家怎么看？</p>
<p>对于那些感到好奇的人：显然，产生所有这些奇迹的AI模型并不是由10000个智能体、消耗数百万美元算力而搭建的定制化装置（像之前用来构造纳维-斯托克斯方程有限时间爆破所用的那样）。相反，它仅仅是OpenAI内部的最新模型——取决于OpenAI安全委员会的建议，该模型可能会在未来几个月内向付费的ChatGPT用户发布！（我9岁的儿子说：“哦，他们绝对不应该发布它。如果它能解开所有那些数学难题，那它绝对不可能是安全的。”）据了解，在他们攻克的难题中，每个问题平均仅消耗了大约3个小时的GPT-Pro级别算力。</p>
<p>此外，如果你还在好奇的话：显然他们在大约8000个问题上测试了该模型。因此，目前它在针对每个问题仅做单次3小时尝试的情况下，“仅仅”解决了它被问及的长期未解数学难题中的约5%——而这些是整个学术圈耗费了数年心血去攻克的问题。</p>
<p>我很高兴看到理论计算机科学界迎难而上。在伯克利的西蒙斯研究所、在德克萨斯大学奥斯汀分校的这里，以及在其他地方，我都听说了研究人员争先恐后研读手稿、试图理解并解释它们的故事——因为除此以外我们还能做什么呢？我们又该如何继续这项我们奉献了大半生的技艺呢？</p>
<p>如果你想体会一下当下的数学界是何种感受，不妨想象一位猎人采集者：他穷尽一生学习如何在残酷无情的原始雨林深处生存，结果一座配有停机坪、恒温泳池和爱彼迎（Airbnb）的巨型度假酒店就在他身旁拔地而起；这位猎人采集者连眼睛都没眨一下，随即说道：“行吧，看来我现在的新工作就是为游客办荒野疗愈静修营之类的了。”</p>
<p>在《量子杂志》（Quanta magazine）中，霍尔达娜·切佩莱维奇（Jordana Cepelewitz）尝试了一个不同的比喻：<br />“这就像是你被瞬间传送到了一座高山之巅。浓雾环绕，你根本不知道自己身在何处，也不知道周遭有什么。你不知道自己脚下的山如何与其它群山相连，你没有任何能帮你探索的装备，也无法带领其他人加入你的行列。如果你是亲自攀登这座山的，你本会切身体验到人体如何适应高海拔和氧气含量的变化。你可能不得不发明导航工具、攀爬陡峭崖壁，或是搭建避难所。你可能会偶遇一位探险同伴，一起在隐秘的山谷中迷路，并发现一种能被制成救命药物的植物。<br />而现在的你，只是被置于峰顶，身陷黑暗之中，与此同时，传送机的制造者却告诉你，它探索这片荒野的能力远胜任何人类。”</p>
<p>对于这些山峰中的任何一座，只要我们足够在乎，我都感到乐观：我们依然能像以往那样拨开迷雾、找寻道路——只不过现在我们是在利用传送机来为我们提供指引。更大的挑战在于，如何在这台机器已经存在的世界里，去培育一个依然在乎“探寻登山之路这一英雄式探险”的社群。（噢，而且我认为这个比喻有一处并不恰当：我们依然拥有彼此，一如既往！）</p>
<p>经验表明，即使到了现在，依然会有人用居高临下的语气解释为什么这一切都不是真的、为什么这一切都不值一提。如果这些人有能力被经验世界中发生的任何事情所打动、有能力针对任何新事实更新认知，那么他们早在几年前就会被打动并完成认知迭代了，根本不用等到局面演变成一场真正的“数学大灾变”（Mathocalypse）。</p>
<p>于是，他们会说：也许那些所谓的解决方案根本就不是解法，不过是“AI垃圾”（AI slop）罢；又或者，那372个被解决的知名未解问题根本就不是真正的数学问题，全都是些被过誉的竞赛题目和琐碎小技。（毕竟，黎曼猜想可还没被解出来呢！）再或者，有着4000年历史的整个数学学科都需要被彻底摒弃：事实证明它无非是一堆解谜游戏和细枝末节；唯一的区别在于，如今这层平庸琐碎终于被揭开了面具。无论如何，真正重要的是，人类创造力真正的核心圣殿尚未被攻破，而且大概永远也不会被攻破；此外，萨姆·阿尔特曼（Sam Altman）和达里奥·阿莫代伊（Dario Amodei）不过是卑鄙可鄙的小书呆子罢了。</p>
<p>如果你依然是那种注定破灭的世界观的拥护者，依然呆在那艘正在沉没的船上，我强烈建议你去读读昨天除了 OpenAI 的“数学大灾变”论文大甩卖之外的另一篇关于 AI 讨论的重磅力作：即斯科特·亚历山大（Scott Alexander）致史蒂芬·平克（Steven Pinker）的公开信。我觉得对此我负有某种责任，因为是我最早向史蒂芬·平克介绍了理性主义社区的存在，也是我最早引荐史蒂芬·平克和斯科特·亚历山大相识（此前他们就互为对方文章的读者）。而现在，斯科特居然要向史蒂芬提出真正的决斗，用枪的那种！</p>
<p>不管怎么说：史蒂芬是我一生的思想偶像，对斯科特来说也是如此；而且我还有幸能将史蒂芬称为我的朋友。但我认为斯科特的那篇博文是我所读过的最为摧枯拉朽的反驳之一。而且我认为斯科特的结论完全正确：面对 AI 风险，史蒂芬现在面临的巨大挑战在于，他需要接受并开始运用一种更加具有“平克式”（Pinkerite）色彩的认识论。</p>
<p>昨晚，我本该仔细研读 OpenAI 那数百篇论文中的一部分，或者撰写这篇博文，但我决定把时间留给孩子们。他们想看电影，于是我提议看一部他们从未看过（而我已经几十年没看过了）的片子，这部电影对于他们即将成长的世界充满了毫不废话的实用指导：《终结者2》。</p>
<p>更新：正如几位读者所指出的，在 OpenAI 的376篇论文列表中，密码学这一子领域引人注目地缺席了！但我的消息来源告诉我，各大 AI 公司现在已经开始小心翼翼且极其低调地调查其最新的内部模型是否能够破解重要的密码协议和密码原语。如果它们真能做到，那么在世界其他地方察觉到同样的问题之前抢占先机，显然是一件好事。</p>
<p>另一条更新：数学与人工智能咨询小组（Advisory Group on Mathematics and Artificial Intelligence, AGMAI）发表了一份措辞极其审慎的声明，既未对 OpenAI 的做法表示背书，也未加以谴责，非常值得一读：<br />“正如数周前宣布的那样，OpenAI 发布了一大批由其内部模型生成的数学成果，汇报了数百个未解问题的解法。这是数学界的一件重大事件，其对数学本身以及数学界的影响都远远超出了单项结果本身。<br />AGMAI 的咨询角色不应被解读为对这些成果影响力的评判，亦非对 OpenAI 获取这些成果所采用流程的认可。我们并不代表整个数学界，唯有数学界整体才能展开所需开展的评估工作。<br />将这项工作公之于众是迈出的第一步。这次发布只是人类理解并将该工作纳入数学知识体系的起点，而非终点。与此同时，数学研究的未来不能仅仅局限于理解 AI 实验室产出的成果。数学家必须能够提出自己的问题，开拓自己的方法，并探索那些尚未被选为 AI 系统能力展示案例的研究方向。公平获取强大的研究工具以及充分的计算资源，是实现这一自由所不可或缺的。<br />我们重申此前发布的关于负责任发布的建议指南。我们已与 OpenAI 进行了讨论，并对其展现出的沟通意愿表示赞赏。虽然我们认为这些讨论具有建设性，但归根结底应由数学界来评估我们的建议在多大程度上得到了有效遵循，以及我们是否应提出其他建议。我们仍将坚定致力于就此类问题与任何前沿 AI 实验室保持沟通，并已与其中数家取得了联系。”</p>

### [加拿大将无限期禁止将精神疾病作为申请安乐死的唯一理由](https://www.theguardian.com/world/2026/oct/07/canada-assisted-dying-mental-illness)
<div class="original-title-sub"><span class="orig-tag">原文</span> Canada to indefinitely bar mental illness as sole reason for access to euthanasia</div>

<div class="article-cover"><img src="https://i.guim.co.uk/img/media/2908b94752481c2982fc99f198fc7cdb3b8216c7/450_0_4418_3535/master/4418.jpg?width=140&amp;quality=85&amp;auto=format&amp;fit=max&amp;s=69e57cb4bb0217233a0e1e06542a7175" alt="加拿大将无限期禁止将精神疾病作为申请安乐死的唯一理由" loading="lazy" /></div>

<div class="article-body" data-article-body="true"><p>该法案是执政的自由党为解决围绕谁有权接受医生协助死亡而日益激烈的争议所做出的努力。</p>
<p>加拿大联邦政府周三表示，将推进立法，禁止仅患有精神疾病的人群接受安乐死。这是执政的自由党为解决国内围绕谁有权获得医生协助死亡所引发的冲突而做出的努力。</p>
<p>根据现行规定，唯一基础健康状况为精神疾病的人员被禁止通过医疗协助死亡（Maid）来结束生命。但这项原定于3月解除的禁令，让议员们在是否允许扩大该Maid项目的适用范围上产生了分歧。</p>
<p>在加拿大，可随时拨打电话 1.833.456.4566，或在美东时间下午4点至午夜12点之间发送短信至 45645 寻求加拿大危机服务机构（Crisis Services Canada）的帮助。在美国，可致电或发送短信至 988 拨打 988 自杀与危机生命线（988 Suicide &amp; Crisis Lifeline），或在 988lifeline.org 进行在线咨询。在英国和爱尔兰，可拨打撒玛利亚会（Samaritans）免费电话 116 123。在澳大利亚，危机支持服务“生命线”（Lifeline）热线为 13 11 14。其他国际求助热线可在 befrienders.org 查询。</p></div>
