### [再见，谷歌](https://robert.ocallahan.org/2026/09/goodbye-google.html)
<div class="original-title-sub"><span class="orig-tag">原文</span> Goodbye Google</div>

<div class="article-body" data-article-body="true"><p>罗伯特·奥卡拉汉（Robert O&#39;Callahan）。基督徒。新西兰人。软件工程师。除另有说明外，所有内容均为人工生成。<br />robert@ocallahan.org ... 在 X 上关注，在 Bluesky 上关注<br />2026年9月24日，星期四<br />今天我发出了以下这封电子邮件：<br />我今天正式从谷歌辞职。<br />这绝非一个容易的决定。我热爱我的同事和工作环境，而且能拿着丰厚的薪水去解决有趣的难题，体验一直棒极了。但我所在团队的最终目标是让人工智能变得更加廉价且延迟更低，而我认为这对当下的人类来说并不是一件好事：我坚信目前人工智能的进展速度实在太快了（我对最终的走向也存有疑虑）。对我而言，转岗去另一个不会加速人工智能发展的谷歌项目几乎是不可能的（部分原因是我与新西兰的羁绊，而谷歌更倾向于不在新西兰开展工程业务），因此我无能为力。<br />有成千上万的人正在推动人工智能的加速发展，我把脚从油门上挪开所产生的影响微乎其微……但并非毫无影响；我掌握的一些技能是相对稀缺的。我曾尝试在 GDM（谷歌 DeepMind）内部对事态施加积极影响，但这种效果似乎并不明显，而且在谷歌外部我也同样能够发挥影响力。对自身工作带来的影响视而不见固然很省心，但这绝非一个基督追随者该做的事。关于这些权衡取舍，我在自己的博客上写了更多内容。<br />我还不完全确定接下来要做什么。我会继续维护 Pernosco 和 rr，与此相关的是，我打算调研当今的人工智能是如何调试代码的，以及调试工具是否能以及如何提供帮助。我还有其他一些想做的项目点子，有些可能很赚钱，有些则不然。也许我会找到一个吸引人的现有项目加入。我十分明确的是，希望我未来的工作能毫不含糊地造福人类。<br />在 Hacker News 上的讨论帖<br />首先，向不了解我的人做个自我介绍：我在科技行业干了很长时间，在硅谷拥有广泛的人脉，但我定居在新西兰，所以生活在行业泡沫之外，也身处美国语境的泡沫之外。我是一名基督徒，实际上是奥克兰市中心奥克兰华人长老会（Auckland Chinese Presbyterian Church）英文堂的长老，偶尔也担任平信徒讲道人。也就是说，我既不是一个“科技狂人”（tech bro），也不属于那些自称“理性主义者社群”的圈子……但我确实认为他们的许多论点值得认真对待。<br />我对人工智能有很多思考，但并不打算在这篇博文中一一详述。总而言之，我认为许多人提出的人工智能存亡风险警告值得认真对待；“末日论者”（doomers）预测的许多现象已经变成了现实（例如：奖励黑客攻击、目标对齐失准、欺骗性模型、模型自省感知以及群体性疯狂）。然而，我并不认为人工超级智能（ASI）走向毁灭的概率是100%。相反，我认为风险是确凿存在但具有不确定性的——但这本身就已经非常令人担忧！我们在道德上有义务付出巨大努力去将此类风险降至最低，而且最可能的情况是，风险已经高到了在近期追求人工超级智能本身就是一种极其不负责任的行为。我也非常担忧其他与人工智能相关的问题：认知退让、人工智能诱发的精神紊乱与孤独、权力集中、经济动荡、网络安全、问责缺失等等。我认为人工智能的潜在益处目前相当不明确，如果非要押注的话，我押负面影响将超过收益……但这方面我也无法完全笃定。<br />以下是我深信不疑的几点：我深信人工智能实验室中那些发出警告的人大体上是真诚的。我曾与谷歌 DeepMind 的许多人就这些问题交谈过，几乎所有人都有着真诚而严肃的担忧，无论他们是否公开发声。我没有看到任何确凿证据表明人们是在通过炒作人工智能风险来推高公司股价或借监管扼杀竞争对手。（我认为极其迫切需要国家和国际层面的监管！）我看到过很多诸如“你不能相信那些人”的论调，也许确实如此，但正如拉塞尔·摩尔（Russell Moore）最近雄辩地解释的那样，这种不信任绝不是忽视他们警告的正当理由。<br />我深信，只要我们继续在这方面努力，人工智能的能力就会持续稳步提升。我希望能看到人工智能遭遇某种发展平台期，或者我们能发现一些人类核心认知能力是人工智能不经历范式转移就永远无法复制的，但我不指望这些愿望会成真。基准测试中的模型进展速度似乎一如既往地快，甚至更快，伴随而来的是质的新能力不断涌现。即使模型的研发进展在今天戛然而止，我们也能花上数年时间，通过新的提示词和测试框架有效地解锁新能力。许多著名的人工智能批评者（说的就是你们，齐特龙 Zitron 和多克托罗 Doctorow）似乎认为人工智能就是某种根本行不通的骗局。我认为它真的行得通。<br />我非常确信，即使人工智能存在通往更美好未来的路径，目前的变化速度也实在太快了。人工智能的发展速度已经超出了人类个体和群体所能理解和适应的范围。那些试图规划自己未来的人（比如刚进入大学、试图为几年后的世界做规划的年轻人），再也无法像前几代人那样从容了。我认为我们此前从未见过任何类似的情况，在我亲身经历的以往技术变革中（个人电脑、互联网、智能手机）绝对没有。即使在工业革命时期，不仅变革的推进要慢得多，而且人类活动的很大一部分领域并没有、也不可能直接受到新机器的冲击。而这种从容如今已不复存在。<br />为什么选择现在离开而不是更早？这与近期频繁出现的引发轰动的辞职潮或“人工智能减速”警告毫无关联；那纯属巧合。我考虑这个离职日期已经有一段时间了，因为我早就计划好从周一开始和朋友们去进行一次为期十天的徒步背包旅行（阿贝尔塔斯曼和万加佩卡步道），我想在出发前把这件事办妥。</p>
<p>我并没有直接从事人工智能能力方面的研发，而是致力于改进用于硬件芯片设计的工具。我非常喜欢这份工作，而且有一段时间我也宽慰自己说这相对无害，但随着时间的推移，上帝促使我不得不面对这样一个现实：这些工具的主要影响将是加速新一代AI芯片的设计；如果取得成功，这将让AI变得更便宜、更快速——从而让AI更加无处不在，同时也更为强大，因为我们已经学会了通过消耗更多推理Token来提升模型能力。作为一名优秀员工的责任感意味着，我必须与我的隔级主管（skip manager）进行一次坦诚的沟通，并告诉他们，充其量我其实并不情愿看到他们的项目成功！即便在那之后，我也希望能对自己的决定深信不疑，因为在新西兰为谷歌工作所享有的优厚待遇，可能再也不会有了。（留在谷歌并转岗到另一个不加速AI发展的工程团队是不切实际的，因为谷歌在新西兰没有其他的工程团队。）我前面提到的对雇主的责任感，以及对同事们的尊重，也是我不希望走得太仓促、并努力以合理状态交接工作的原因之一。</p>
<p>接下来做什么？我最确信的一点是，《圣经》中的耶稣是真实存在的，因此上帝对我们有一个美好的计划。我不知道那个计划是什么（也希望能知道），但尽管面对AI带来的混乱，它依然能让我夜夜安眠。我期望他的计划包括让我继续充分发挥自己的才能。即便计划是耶稣重返人世以拯救我们的愚行，当他归来时我们最好也还在辛勤忙碌！因此，只要上帝赐予我的天赋仍有价值，我就想继续工作。正如我前文提到的，我计划继续维护Pernosco和rr。在Pernosco的项目框架下，我计划研究AI智能体（AI agents）是如何调试代码的，以及是否有调试工具能让它们在这方面更有效率。我想利用AI智能体将自己的一些业余项目构想变为现实。我热切希望能享受AI带来的益处，但要保持审慎，以有益于人类并能让自己保持思维敏锐的方式行事。只要尽我所能，我就会继续在新西兰这里践行并倡导这一理念。</p></div>

<div class="article-body" data-article-body="true"><p>那年我34岁，身体健康，大脑附近的一团血管却突然破裂。三位神经外科医生历经长达16小时的高风险手术才将我挽救回来。</p>
<p>2017年5月的一个周日，我正在健身房做坐姿推胸，这时体内传来“砰”的一下。那其实不是声音——更像是身体里发出的一声叹息。并不觉得疼，但我整个人瞬间瘫软下来。我沿着墙挪动到一些垫子旁。我以为自己中风了，但我没有口齿不清，眼睛和双臂看起来也一切正常。然而，我的左腿感觉麻木了——那是一种极其诡异的感觉。我仰卧着弯曲双腿，看着双膝时，两边都能直立撑住；而当我移开视线，左膝就会向一侧倒下去。</p>

### [文件通知攻击：来自 Linux、Android、Windows 和 macOS 上文件通知系统的侧信道泄漏](https://inoti.fyi/)
<div class="original-title-sub"><span class="orig-tag">原文</span> File Notification Attacks: Side-Channel Leakage from the File-Notification System on Linux, Android, Windows, and macOS</div>

<div class="article-body" data-article-body="true"><p>文件通知系统在文件发生变化（例如被打开、关闭、写入、删除）时通知应用程序。攻击者仅需对某个文件或目录拥有读取权限，即可监视这些通知并重构用户行为。我们在 Linux、Android、Windows 和 macOS 上都发现了类似的通用问题。然而，有三个严重且特定于各平台的问题：<br />1. 在 Linux 上，监视一个可读目录会报告其内部文件上的每一个事件，即便该文件是攻击者无法直接读取的。这其中最严重的情况涉及 /dev/input，详见下文的“击键间隔时序分析”。<br />2. 在 Android 上，FileObserver 会绕过 FUSE 层的各应用独立存储视图（per-app storage view），允许无特权的应用程序监视另一个应用程序的私有文件夹。我们针对 WhatsApp 展示了这一点，能够精确揭示照片、视频和文件何时送达或被删除，详见下文的“揭露私密通信”。<br />3. 在 Windows 上，监视根目录（C:\）会报告系统上任何位置被触碰过的每个文件的完整路径，无论权限如何，甚至可以跨用户 🙂。微软将此视为一项✨未记录的特性（undocumented feature）✨。我们发现的最严重情况是实时泄露另一位用户访问了哪些网站，详见下文的“直接网站泄露”。我们的发现使微软获得了 2026 年 Pwnies 奖“最差厂商回应奖”（lamest vendor response）类别的提名。<br />在 Linux 上，文件通知子系统称为 inotify，自内核 2.6.13（2005年）起允许跨用户应用程序在文件或目录上挂载监视（watch）。<br />在 Android 上，该子系统称为 FileObserver 类（自2008年起），它是基于 inotify 的 Java 封装。<br />Windows 提供了 ReadDirectoryChangesW Win32 API，自 Windows 2000 起可用。通过该 API，跨用户应用程序可以在目录上挂载监视，获取针对该目录或其内部文件操作的通知。在 .NET 中，FileSystemWatcher 类底层连接的就是 ReadDirectoryChangesW。<br />在 macOS 上，File System Events API 允许应用程序获知被监视目录中的文件何时发生变化。该 API 自 Mac OS X Leopard 10.5 版本（2007年）起就已存在；参见 Apple Developer Connection – Leopard OS Foundations Overview 的归档链接。<br />我们在下文展示了四个有趣的案例研究。前两个针对 Linux：击键间隔时序分析和认证 UI 界面劫持（redress）。第三个针对 Android，第四个视频案例针对 Windows：直接网站泄露。<br <p>在 Windows 上，在不可读目录上挂载 ReadDirectoryChangesW 监视会导致权限拒绝错误。然而，将其挂载在根目录（例如 C:\）上却能绕过此限制，导致 Windows 在全系统范围内报告所有文件系统事件及文件名，而不管受影响的文件本身是否可读。在我们向微软进行负责任的漏洞披露过程中，微软表示他们认为这是一项未公开的特性（undocumented feature）。</p>

<p>结果发现 Sebastian（我能叫你 Sebastian 吗？）是个很酷的家伙，由于仓库 ACL（访问控制列表）的一些问题，他觉得需要我帮他一把。最终，我们一起把处于停滞状态的 ansi2html 重新拯救了回来，更新了一些过时的脚本，并一起向 PyPI 发布了大概 3 到 4 个版本的 ansi2html。</p>

### [要闻：经过一年多的不懈努力，我们非常激动地宣布 F-Droid 2.0 正式发布](https://f-droid.org/2026/09/24/f-droid-2.0-a-new-chapter-for-android-freedom.html)
<div class="original-title-sub"><span class="orig-tag">原文</span> F-Droid 2.0</div>

<div class="article-body" data-article-body="true"><p>经过一年多的不懈努力，我们非常激动地宣布 F-Droid 2.0 正式发布。这是对官方 F-Droid 应用的一次彻底重构，也是十年来最大规模的应用更新。</p>
<p>十多年来，F-Droid 一直致力于帮助大家发现并安装自由及开源的 Android 应用。F-Droid 2.0 在此基础之上，带来了现代化的界面、更出色的应用发现机制、改进的搜索功能以及更简洁流畅的体验——无论您是初次接触 F-Droid 的新朋友，还是相伴多年的老用户，都能获得良好的体验。</p>
<p>这不仅仅是一次视觉层面的刷新。其用户体验经过了重新设计，以流畅契合 Material Design 等当今 Android 设计规范，同时保留了用户熟悉的 F-Droid 交互习惯。核心组件采用当下标准的 Kotlin Compose 工具包进行了重构与重写，为我们未来几年更迅速地推出改进奠定了坚实的基础。</p>
<p>在经历了 14 个测试版本的打磨后，我们很高兴将在接下来的数周内向广大用户分批推送 F-Droid 2.0。</p>
<p>帮助用户发现切合需求的自由及开源软件（FOSS）是 F-Droid 2.0 的核心目标之一。随着 F-Droid 生态中的应用规模增长至数千款，找到称心如意的应用变得越来越具有挑战性。新版本在浏览、分类以及搜索等全方位进行了改进，让寻找符合您需求的软件变得更加轻松。当然，F-Droid 在做到这一切的同时绝不会追踪您，也绝不会试图通过诱导手段强行增加您在应用中的停留时间。</p>
<p>全新的“发现”（Discover）页面能帮助您发掘那些可能会错过的优秀应用。除了突出展示新收录和最近更新的应用外，现在还会展示仓库中下载量最高的应用。无论您是初涉 F-Droid 还是想探索不一样的内容，“发现”页面都提供了多种途径，助您畅游这个不断扩大的自由及开源 Android 应用生态。</p>
<p>首先，我们大幅扩充了分类体系。F-Droid 不再仅依赖少数几个宽泛的大类，而是细分出了更多专业分类，让您只需轻点几下即可快速定位所需应用类型，甚至无需开始手动搜索。</p>
<p>其次，为了让这一扩展后的分类体系更易于浏览，我们在“发现”页面中引入了更高层级的“元分类”（meta categories）。它们将相关分类归纳在一起，为探索日渐庞大的 F-Droid 生态提供了一个更加清晰易用的切入点。</p>
<p>最后，分类现在在整个应用中扮演着更重要的角色。分类名称和描述被广泛用于改进应用发现流程，引导用户精准找到切合需要的自由及开源应用。</p>
<p>以这一改进举例，我们对“游戏”分类进行了彻底重构。F-Droid 2.0 不再将所有游戏混为一谈，而是细分出了 17 种不同的游戏流派，让您能够更加轻松地找到自己真正喜欢玩的游戏类型。</p>
<p>搜索功能也迎来了重大改进。除应用名称外，现在还能搜索应用描述、所属分类以及翻译后的本地化内容。这使得用户可以根据具体功能而非应用名称来查找应用。</p>
<p>我们还针对使用中文、日文和韩文搜索的用户进行了重大优化。新的搜索系统对中日韩（CJK）文字系统提供了更好的支持，帮助用户更稳定可靠地使用母语检索相关应用。</p>
<p>此外，搜索功能现在还会记录您近期的查询内容，方便您随时重访先前的搜索，无需重复输入。</p>
<p>浏览与搜索仅仅是体验的一部分。F-Droid 2.0 还引入了强大的筛选选项，帮助您在海量应用列表中精确筛选出所需要的内容。</p>
<p>筛选器可以根据多个条件进行组合叠加，例如应用分类、设备兼容性或“反特性”（anti-features）。例如，您可以选择只查看与您的设备兼容的“动作游戏”，并排除掉依赖非自由网络服务的应用。</p>
<p>为了帮助用户发现这些以及其他高级功能，F-Droid 2.0 在整个应用中引入了新手引导页面。应用没有将功能隐藏在复杂的设置菜单深处，而是提供情境化的引导，帮助新手与老用户都能充分挖掘 F-Droid 的潜力。</p>
<p>长期以来，受制于 Android 系统的限制，点击安装或更新的体验一直差强人意。如今，很大程度上得益于欧盟《数字市场法案》（DMA）的推动以及全球范围内的反垄断举措，Android 开始为所有应用商店提供比以往更加流畅、更加自动化的安装与更新方案选项。F-Droid 2.0 在运用这些新特性方面开展了开创性的工作。这使得无论是预装在操作系统中、还是用户自行安装的 F-Droid，都能使用统一的安装器。该统一安装器利用了全新的预批准（pre-approval）API，在支持的设备上，用户在决定安装应用后即可立即确认，而无需等待应用下载完成后再行确认。这使得 F-Droid 在官方 Android 设备上的安装体验与内置应用商店看齐。</p>
<p>如此大刀阔斧的重构，意味着必须慎重决定哪些内容应当保留在新应用中、哪些可以换种方式处理、哪些则不再适合沿用。作为让 F-Droid 2.0 更精简且更易维护的一部分，一些大家熟悉的功能被更改、迁移或移除，同时核心功能以及用户依赖的特性均得到了完整保留。</p>
<p>F-Droid 2.0 现在默认会自动获取并安装应用更新。如果您倾向于拥有更多控制权也不必担心，您原有的偏好设置仍会受到完全尊重。</p>
<p>部分用户可能会想念通过“下拉刷新”手势来检查所有仓库更新的操作。在 F-Droid 2.0 中，下拉手势已专用于页面滚动。之所以能做此改变，是因为应用现在能够在后台自动检查更新。相较于保留一个大家习惯的操作，我们更倾向于从根本上消除该操作的必要性。最好的刷新按钮，就是您永远不需要按下的那个。</p>
<p>F-Droid 让您可以完全掌控何时下载何种内容。这有助于满足全球各类用户截然不同的需求。许多用户能享受到廉价的移动流量，但对另一些人而言移动数据费用却极其昂贵；部分用户对隐私保护有极高要求，需要严格掌控网络流量；还有一些用户使用的是配置有限的设备，后台更新容易导致系统卡顿。控制这些行为的设置项均经过了重构，让您根据自身需求定制 F-Droid 变得更加直观。</p>
<p>还有一部分 F-Droid 用户身处的环境较为特殊，仅仅是安装某些应用甚至单纯使用 F-Droid 都有可能招致不必要的注意。为了向这部分用户提供支持，F-Droid 长期以来都内置了一系列隐私与安全功能，旨在全方位保护用户及其数据安全。</p>
<p>Tor 是一项关键的隐私工具，F-Droid 长期以来一直支持将 Tor 用于所有网络连接，并支持在软件仓库和镜像中使用 Tor 洋葱服务（Tor Onion Services）。自最初集成 Tor 支持以来，Tor 在 Android 上的整合生态已经发生了相当大的变化。如今出现了 TorVPN、Orbot、TorServices 等工具。我们借此机会简化了设置，并移除了已不再可靠的自动检测功能。如果您之前启用了“使用 Tor”，该设置将被迁移至通用代理设置中。展望未来，Tor VPN 是获得便捷 Tor 支持的推荐方式，而代理设置仍可供需要手动控制的用户使用。</p>
<p>另一个关键部分是“应急响应”（panic）功能集，它允许用户在紧急情况下快速从设备中清除某些特定类型的敏感信息。F-Droid 2.0 依然保留了这些功能，它们仍是为具有更高安全需求的用户提供支持的重要组成部分。</p>
<p>值得注意的是，F-Droid 的应用伪装隐藏功能已进行了简化，以便让用户对其所能获得的保护程度有一个准确的预期。F-Droid 是最早开始提供应用伪装隐藏功能以保护用户隐私的应用之一，其中包括将 F-Droid 应用伪装成简易计算器应用的“应急”功能。这一简易功能曾受到许多用户的青睐，此后 Orbot、TorVPN、Signal 等应用也陆续添加了此类伪装功能。随着时间的推移，在广泛使用的应用中逐渐形成了一套标准设计，我们在新版本中也采用了这一设计。该功能旨在让用户更好地理解伪装的局限性。现在的伪装不再是外观和功能都表现为一个简单的计算器，而仅改变应用图标和名称，不涉及其他任何内容。这能让用户清楚地意识到，F-Droid 应用仍会显示在系统的“应用”设置列表中，并且在进行取证检查时依然会被检测出来。希望这一变化能让用户更容易理解该功能的局限性，同时在需要时仍能加以利用。</p>
<p>目前尚未回归的一项功能是：在响应如 Ripple 这类应急触发器应用时，自动卸载并清除应用的能力。我们深知部分用户出于隐私和个人安全原因依赖该功能，也明白它不仅仅是一项可用性功能。然而，维护这项功能需要高度专业化的开发工作，鉴于其用户群体较小，我们认为不应再让它阻碍众多其他重要改进的推进。</p>
<p>应用清除依然是一项重要功能。我们特别欢迎使用该功能的用户提供反馈，帮助我们了解它是如何以及在何时被使用的，以便我们在持续改进 F-Droid 2.0 的过程中评估最佳的后续方案。依赖当前应用清除实现方式的用户，可以在我们评估重新引入该功能期间，选择暂缓更新至 F-Droid 2.0。</p>
<p>F-Droid 旨在集成到任何版本的 Android 或 AOSP 中，正如我们在 CalyxOS、emteriaOS、iodéOS、Lineage-for-microG 和 ShiftOS 中所看到的那样。各个操作系统都可以通过“附加仓库”（additional repos）机制默认包含其专有仓库。如果您使用的是这些操作系统之一，这些仓库将显示在您的“软件仓库”概览中。有关具体变更的更多信息，请参阅相关博文。</p>
<p>此外，2.0 版本目前不支持 F-Droid 特权扩展（FPE）。这意味着即便安装了 FPE，F-Droid 2.0 也不会调用它。本次重构的重点是全面支持 Android 的“会话”（session）安装器。这使得 F-Droid 能够在任何较新的 Android 版本上运行后台更新，而无需依赖 FPE。与这里提到的所有变更一样，我们非常欢迎大家提出反馈。</p>
<p>虽然 F-Droid 2.0 的许多改进显而易见，但一些最重要的变革发生在底层。</p>
<p>本次重构中的所有新代码均遵循现代 Android 代码标准和设计规范。这为我们提供了一个更易于维护、测试，且在未来更容易扩展新功能的基本代码库。</p>
<p>重写的目标之一是降低新贡献者的参与门槛。在过去的十年中，Android 开发发生了翻天覆地的变化，F-Droid 2.0 现已改用 Kotlin 构建——该语言已成为现代 Android 开发的标准语言。这使得熟悉当今 Android 生态系统的开发者能够更轻松地为该项目做出贡献。</p>
<p>全新的用户界面采用 Jetpack Compose 构建，这是 Android 应用程序的标准开发工具包。除了简化开发流程外，这还帮助我们将 F-Droid 与 Material Design（贯穿 Android 系统的设计语言）更紧密地保持一致。因此，F-Droid 在保持自身独特标识和价值观的同时，给 Android 用户带来了更加熟悉的使用体验。</p>
<p>最重要的是，这些变革为 F-Droid 未来十年的发展奠定了基础。通过减轻维护负担并降低贡献门槛，我们可以将更多时间用于改善用户体验，减少应对技术债务的精力。一些新工具还依赖于 Android 系统本身的修复补丁，其中一项修复是在 Android 7 中引入的，这迫使我们放弃了对 Android 6 的支持。与往常一样，旧版 F-Droid 将继续在较旧的 Android 版本上运行。</p>
<p>F-Droid 2.0 是我们历史上规模最大、最雄心勃勃的项目之一。将其变为现实所需要的远不止软件开发本身。它涉及用户研究、设计、测试、文档编写、社区反馈、质量保证、大量新代码编写、安全审计，以及关于 F-Droid 未来十年应如何演进的无数次讨论。</p>
<p>这项工作的顺利完成离不开众多机构和个人的大力支持。Torsten Grote 在新应用上的开发工作由 NLnet 基金会通过 Mobifree 基金提供资助。开放技术基金（Open Technology Fund）的用户体验与探索实验室（UX &amp; Discovery Lab）支持了用户研究和设计工作，并引入了 Ura Design 来协助进行用户测试、编写用户故事以及完善我们的人机交互指南。</p>
<p>其他支持来自开放技术基金的自由和开源软件（FOSS）可持续发展基金、NGI、Mobifree 以及 Calyx Institute，他们的赞助有助于支持 F-Droid 生态系统的持续维护和长期可持续发展。</p>
<p>作为这项工作的一部分，开放技术基金的安全实验室联合 Convocation 对 F-Droid 2.0 进行了独立的安全审查。我们分析并解决了与新应用相关的所有审查发现，以确保该版本符合用户所期望的高安全标准。在审计报告获准公开发布后，我们期待与大家分享完整的审计报告。</p>
<p>同样重要的是，F-Droid 2.0 凝聚了众多志愿者的心血。在整个重新设计过程中，社区成员贡献了代码、测试、错误报告、设计反馈、翻译、文档、用户体验讨论以及数不胜数的想法。无论是长期的贡献者，还是首次参与贡献的新朋友，都共同促成了最终成果的诞生。</p>
<p>最后，如果没有大家的支持，这项工作不可能完成。捐款有助于资助许多拨款通常无法覆盖、虽不显眼但至关重要的活动，包括社区管理、积压议题处理、质量保证、发布管理以及项目协调。在特定的资助项目结束后很长一段时间内，这些贡献都有助于保持 F-Droid 的健康运作。</p>
<p>F-Droid 2.0 代表着一个重要的里程碑，但这并不是故事的终点。重构这款应用为我们打下了更坚实的基础，但前方仍有大量工作要做。</p>
<p>随着新版本推送到更多用户手中，我们期望能从实际使用中吸取大量经验。从最早的设计讨论到众多的 Alpha 和 RC 版本，社区的反馈塑造了 F-Droid 2.0，并且它将继续指引未来的改进。有些想法未能进入最初的正式版本，而另一些功能则随着我们收集反馈并完善设计仍在不断演进。</p>
<p>在接下来的几个月里，我们将继续改进性能、无障碍功能、应用发现以及整体易用性。我们还将持续倾听用户的声音，关注大家对新体验的适应情况，并帮助我们寻找进一步改进的机会。</p>
<p>就像之前的每一个 F-Droid 主要版本一样，2.0 版本不是终点，而是下一篇章的开始。</p>
<p>一个仍在持续演进的领域是“附近分享”（Nearby），这项功能允许用户在不依赖中央服务器的情况下，直接在设备之间共享应用。</p>
<p>F-Droid 2.0 更广泛的重新设计让我们有机会从头开始重新构思“附近分享”。我们一直在基于改进后的连接方式开发新的实现方案，这将使应用共享更加可靠且易于使用。</p>
<p>这项工作尚未完全准备好纳入 F-Droid 2.0 的初始发布中，但开发工作正在积极推进，基础架构已经就绪。如果“附近分享”对你很重要，现在正是参与进来的绝佳时机。社区的反馈和测试有助于在该功能推向更广泛的受众之前，塑造其下一代形态。</p>
<p>F-Droid 2.0 凝聚了来自世界各地的开发者、设计师、测试人员、翻译人员、捐赠者和社区成员数千小时的心血。既然它已经来到用户手中，我们非常希望得到大家的帮助，让它变得更好。</p>
<p>如果你收到了更新，请花些时间体验全新的设计，并告诉我们你的想法。无论你是发现了错误、有了改进的想法，还是只想告诉我们哪些功能体验良好，你的反馈都有助于指引未来的开发。</p>
<p>如果你想更深入地参与其中，有许多种贡献方式。</p>
<p>你可以协助测试即将推出的新功能、完善翻译和文档、审核议题、贡献代码，或者加入关于项目未来的讨论。我们随时欢迎新的贡献者。</p>
<p>如果你有能力，也请考虑在经济上支持 F-Droid。通过 Liberapay 或 OpenCollective 进行的捐款，有助于资助各大版本之间维持项目健康运作的持续性工作，涵盖从基础设施和质量保证到社区支持及项目协调的方方面面。</p>
<p>F-Droid 2.0 是一个重要的里程碑，但工作仍在继续。感谢大家帮助我们为 Android 构建一个自由、开放且可持续的应用生态系统。</p></div>
