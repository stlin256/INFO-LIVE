### [Web开发教育之死](https://molily.de/web-dev-education/)
<div class="original-title-sub"><span class="orig-tag">原文</span> The death of web development education</div>

<div class="article-body" data-article-body="true"><p>挽救一个正在消失的领域<br />在个人博文中，鲍德尔·比亚纳松（Baldur Bjarnason）讲述了自己如何在不同领域和岗位上工作：作家、出版人、顾问、开发者、教育工作者，以及广播电视制作人。然而从长远来看，这些工作在经济上都不可持续。<br />更让人雪上加霜的是，各自的圈子都在排斥那些不符合其狭隘领域定义的跨学科人才。例如，面对一份“创意”工作，你会被认为过于“偏技术”；而面对一份“技术”工作，你又会被视作过于“偏创意”。<br />比亚纳松描述了生成式AI对Web开发教育带来的冲击：<br />“我所有的培训和教育项目一个接一个地中断了。我身边大多数靠卖课和培训谋生的同行都在关闭业务。Web开发电子书的需求更是断崖式下跌。[……]<br />软件开发者并没有全都转去用智能体（agent）来写代码，但对于如今充当Web开发‘教育’角色的东西，他们似乎全都转向了容易出错、墨守成规且充满不确定性的聊天机器人。”<br />许多过去依靠Web开发培训和开发者关系（DevRel）谋生的独立教育工作者纷纷表示，生成式AI毁掉了他们的生计。<br />阿克塞尔·劳施迈尔（Axel Rauschmayer）是全球高产的JavaScript和TypeScript作家之一。他过去常将自己的电子书作为免费在线图书发布。自2005年以来，他一直在其极具影响力的博客2ality上详解ECMAScript等Web技术细节。如今他写道：<br />“我靠卖书获得的收入，从足以维持生活（2024年）直接跌至归零（2026年）。<br />我博客和图书（此前可在线免费阅读）的访问流量增长超出了我目前的承受能力。几乎所有流量都来自AI爬虫，因此根本没有任何广告收入。<br />因此，我决定将我的博客和图书下线，以便思考下一步该怎么做——尤其是在AI公司肆意窃取我劳动成果的背景下。”<br />（劳施迈尔目前仍以合理的价格出售他的JavaScript和TypeScript图书！）<br />萨尔玛·阿拉姆-内勒（Salma Alam-Naylor）曾在开发者关系领域工作，这个岗位长期承受着证明自身存在价值的压力。企业期望DevRel能带来短期财务收益——而这从其本质上来说是不可能的。这导致阿拉姆-内勒陷入了身心俱疲和焦虑之中。在此情境下，她写道，AI正在扼杀开发者教育：<br />“开发者们不再聚集在网络空间中学习、教学以及分享令人兴奋的项目，而是漫无目的地刷屏，以获取急需的短内容多巴胺刺激（因为这世界上的可怕之事比以往任何时候都更加挥之不去）。[……] 许多开发者已经用与那些可怕聊天机器人的对话，取代了真实的同行交流。[……]<br />对于教育工作者来说，未来显得十分惨淡。我们用心为真实人类读者精心打磨的丰富课程体系，如今却被预测算法肆意窃取和反刍。那些聊天机器人带着阿谀奉承的语调，被蓄意设计出来，将我们自身的个性、辛勤付出和精湛技艺彻底从等式中抹去。<br />我唯一能得出的结论是，在这个动荡的行业中，我的经验、技能、同理心和教学专长已不再具有过去的价值（如果说它们曾经真正拥有过的话？）。<br />阿拉姆-内勒决定接受一份薪水较低且无需公开露面的开发者工作。她决定淡出网络。<br />她引用了乔希·W·科莫（Josh W. Comeau）的经历，后者长期围绕Web技术制作在线课程、撰写深入研究的文章以及互动教程。生成式AI同样摧毁了他的商业模式：<br />“我已经和几位课程创作者聊过了，我们都看到了同样的趋势。收入下滑超过50%。与我们内容互动的人越来越少。大家转向了大语言模型，而这些模型在未经许可且没有报酬的情况下，把我们的劳动成果吞噬殆尽，然后再反刍出来。”<br />科莫指出，在大语言模型泛滥的情况下，人们根本没有动力去制作高质量的免费内容。<br />来自“Web Dev Simplified”频道的YouTube内容创作者凯尔·库克（Kyle Cook）透露，他的编程教程播放量以及随之而来的收入基本上被腰斩。<br />“我现在的收入恰好只有一年前的一半。[这]绝对无法维持一份全职工作。[……] 作为内容创作者，在编程内容几乎赚不到钱、制作极其困难的情况下，几乎没有任何动力去制作它——要知道，我完全可以转去做一个关于最新AI模型的视频，既好做，赚钱又多，播放量还更高。[……] 几乎再也没有理由去制作编程内容了。我还在做的唯一原因，是我从中看到了价值，能从中获得乐趣，而且我能通过YouTube广告分成以外的其他途径赚到钱。”<br />雷切尔·安德鲁（Rachel Andrew）是知名技术作家，也是多部Web主题图书和文章的编辑。在一系列博文中，她反思了生成式AI对技术出版业的影响。她指出，生成式AI已经破坏了领域专家（初稿作者）与负责校对、事实核查及润色文章的编辑之间的合作关系。<br />“编辑们不得不投入更多精力进行严格审查，因为AI工具可能会引入不易察觉的不准确之处，而原作者甚至毫无察觉。AI可能会极度自信地给出错误答案，如果文字看起来很通顺，人们很容易忽略其本质上是一派胡言的事实。作者们想要节省一些时间，却给编辑团队带来了额外的工作负担。”<br />安德鲁认为大语言模型是一个有用的工具，但强调其应用领域非常有限，其输出必须经过对最终成果高度负责的人员进行审查。<br />她进一步质疑AI是否真的提高了生产力。安德鲁指出，潜在的生产力提升源于生成式AI对某些任务的自动化，然而这些任务即便不用AI也同样能够实现自动化，AI只不过让不会编程的人更容易上手。如今随着越来越多诸如API参考手册之类的信息以机器可读的形式提供给LLM，执行非AI自动化也变得更加容易。<br />安德鲁再次指出，人们感受到的个人生产力收益，可能仅仅是将工作转嫁给了其他人。例如，作者将工作转嫁给技术编辑甚至读者。“你可能觉得自己效率更高了，但实际上你所做的只是转移了工作，让别人的工作或体验明显恶化，同时降低了质量。” 总之，她发问道（强调为原文所加）：<br />“如果现实中生产力相对微弱的提升原本可以通过教会更多人使用现有工具或简单代码自动化任务来实现，我们又如何能证明AI所付出的成本（包括财务、环境和人力成本）是合理的？企业为什么不鼓励员工在可能的情况下使用非AI方法，仅在能真正创造价值的地方保留AI？考虑到社会成本，以及企业吸纳和培养人才所能带来的益处，权衡之下，或许即便是在需要AI的那些任务上，由人类来完成也会更好。”</p>
<p>首先，也是最重要的一点，我想正视这些经历并放大这些声音。生成式人工智能（GenAI）对 Web 开发教育和学习造成了灾难性的影响。它威胁着那些致力于让 Web 技术通俗易懂、培养下一代 Web 创作者和开发者的作家、教师及传播者的生计。</p>
<p>目前并没有显而易见的短期解决方案。但这并没能阻止某些人发表下意识的应激反应。我不会贴出这些博客文章的链接，但它们大致是这种论调：</p>
<p>这些反应本质上与“要么登上 AI 列车，要么走向毁灭”如出一辙。此类评论无异于在伤口上撒盐。</p>
<p>我无法给那些教育工作者提供任何建议。但我确实设想了一种更具同理心的回应：</p>
<p>我由衷赞赏您作为教育者、作家、研究者或自由开源软件开发者所做的工作。衷心地感谢您。很遗憾 AI 榨干了您以及您这一行业的所有乐趣。</p>
<p>我承认 AI 公司侵占了您的劳动成果，摧毁了您的经济生计，并动摇了您所在领域的根基。</p>
<p>这种局面绝不会因为引入更多 AI、制造更好的 AI，或是基于 AI、为了 AI 进行开发而好转。</p>
<p>在科技巨头与法西斯运动勾结的大背景下，这听起来或许有些遥不可及，但最起码的要求应当是迫使 AI 寡头为他们强加给 Web 社区等群体的危机买单。我们必须剥夺剥夺者。</p>
<p>面对 Web 开发教育遭到的破坏，我想捍卫某些特定价值观。在之前的一篇博文中，我曾讲述过自己当年是如何通过一个由志愿者主导的非商业文档项目踏入 Web 开发大门的。</p>
<p>这类倡议使 Web 走向了大众化，因为它们帮助了各行各业的人建立自己的网站和社区——本地小企业、自由职业者、艺术与手工艺团体、社区自治项目、学校和幼儿园、体育俱乐部、LGBTQ+ 群体、粉丝圈等。</p>
<p>如今，我们经常从生成式 AI 的鼓吹者口中听到“大众化”（democratize）这个词，但它的实际含义却截然相反。AI 集中了权力并将知识商品化，而不是传授技能和深刻理解。</p>
<p>Web 本身是一种彻底民主化的媒介。眼下，科技寡头和法西斯运动正企图瓦解其蕴含的彻底性潜力。我们必须确保每个人都能塑造 Web。</p>
<p>参与独立学习社区，使用基于伦理原则的开放技术，并构建一个共享且包容的数字基础设施，这是一种自我赋权与解放的行动。</p>
<p>人类需要拥有学习、研究和教授 Web 发布技能的资源。正是人类承担了所有核心的知识与教育工作，他们应当为此获得报酬。</p>
<p>这听起来是老生常谈，但生成式 AI 的倡导者却拒绝承认。他们任由科技巨头肆意侵占 Web 教育工作者的劳动成果。在这点上我们绝不能妥协退让。</p>
<p>关于整个 Web 开发领域，比亚纳森（Bjarnason）得出了一个暗淡的结论（重点为作者所加）：</p>
<p>“我不再热爱我的领域了，因为这个领域已经荡然无存。假定那里还留存着什么，本身就是一个错误。你心中的那种感觉，并不是对自己所选领域发生变迁的沮丧。它是对一个在一夜之间消失殆尽的领域的怀念。如今普遍被称为 Web 开发的东西，与我们多年来建立的领域毫无相似之处。我们所学到的一切都被弃若敝屣，因为各大公司认定这一切都已经被编码进了它们所选的大型语言模型中。”</p>
<p>假若事实真当如此，那我确实犯了怀旧之罪。我只是坚信 Web 具有强大的韧性，它没那么容易被关进牢笼。要重建 Web 开发领域，需要一个彼此支持的人际网络——共同掌握 Web 技术，挖掘最佳实践并确立全新规范，并分享各自的真知灼见。</p></div>

<div class="original-title-sub"><span class="orig-tag">原文</span> Pidgin 3.0 Alpha 3 2.97.0 has been released</div>

<div class="article-body" data-article-body="true"><p>该版本仍可在 SourceForge 上获取，但感谢 Fastly 为我们提供了新的 CDN，您现在也可以在 fastly.imfreedom.org 下载该版本。它很快也会在 Flathub Beta 上线。</p>
<p>如果您不想使用 Flathub Beta 的方式，README.md 中提供了在本地构建 Flatpak 或安装到 meson 开发环境（meson devenv）的构建说明。这两种方法都能避免直接安装到操作系统环境中——这也是目前推荐的方式，因为目前尚无简便卸载该应用的方法。</p>
<p>与以往的版本一样，这是一个定时发布的版本。它是我们当前开发进展的一个快照，供其他折腾爱好者和开发者尝鲜试用。但再次提醒，它并不适合普通终端用户日常使用。</p>
<p>大部分功能尚未实现，用户界面几乎未经过任何润色，并且存在非常非常多的 Bug。因此，我们恳请软件包维护者目前切勿将其打包分发给普通用户，因为潜在的技术支持需求将超出我们的承受能力。</p>
<p>在这个开发周期中，我们进行了大量的底层维护工作，面向用户的改动并不算多，但仍有几处亮点值得一提！</p>
<p>独一无二的 Hylke Bons 慷慨地为我们提供了一套全新的在线/状态图标。您可以在下方的联系人列表截图中看到它们。抱歉，我忘记把离线用户截进去了。</p>
<p>现在，账户在断开连接后将自动尝试重新连接。目前它基于每次尝试间隔 1 分钟的简单静态计时器运行，未来可能会进一步改进。与 Pidgin 2 不同的是，它会一直无限次地尝试重新连接。</p>
<p>更酷的部分之一是，这现在可以在调度器（scheduler）中直观地看到——如下方所示，该界面同样未经任何打磨。</p>
<p>我们终于创建了 PurpleHistory 类，这就是我们现在用于表示对话中消息的方式。虽然这方面还有大量工作要做，但各协议现在已经可以通过 Purple.Conversation:history 属性来访问并查找消息，以及添加新消息。</p>
<p>未来还将提供供用户界面向协议请求加载消息的 API，不过目前尚未完全就绪。</p>
<p>我们将插件管理重新移回了单独的对话框中。在 GPlugin 发生一些改动后它可能还会更新，但您可以在下方先睹为快。</p>
<p>我们移除了 Zulip 协议插件上的“开发中”（in-development）标签。虽然该协议仍有很长的路要走（包括添加频道支持），但私信（DM）功能已经足够稳定，让我们有信心移除该标签。</p>
<p>这意味着在创建新账户时，它现在默认会出现在协议列表中。</p>

<p>我们已经为 Alpha 4 提交了大量议题（tickets），您可以关注 Alpha 4 的燃尽图（Burn down Chart）以获取最新进展。</p>
